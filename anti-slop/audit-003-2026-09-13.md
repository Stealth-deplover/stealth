## Findings

### 1. Resource detail views conflate initial loading with not found

- Priority: HIGH
- Rules: R-27 and C-4
- Evidence:
  - `console/src/features/sites/site-detail-view.tsx:52-89` reads
    `query.data?.site`, handles `query.error`, and then renders `Site not
    found` when `site` is absent. There is no initial `query.isPending` branch.
  - `console/src/features/sites/site-detail-view.tsx:258-267` does the same
    for a deployment detail query and renders `Deployment not found` before
    the first response has completed.
  - `console/src/features/functions/function-detail-view.tsx:63-120` reads
    `query.data?.function`, handles errors, and then renders `Function not
    found` without an initial loading state.
  - `console/src/features/functions/function-detail-view.tsx:448-457` has the
    same pending-versus-not-found ambiguity for function deployments.
- Impact: A normal first request can tell an operator that a resource was
  removed or is outside the project while the API is still pending. Loading,
  empty, and error states are not distinguishable.
- Suggested direction: add an explicit shared loading branch for each primary
  detail query before the not-found branch, while preserving retryable errors
  and the completed-response not-found state.

### 2. Navigation overlays treat pending or failed data as empty

- Priority: HIGH
- Rules: R-27 and C-4
- Evidence:
  - `console/src/components/navigation/context-switchers.tsx:197-275`
    reads projects with `useProjects` but does not consume a loading or error
    state. Until the request resolves, it renders `No projects in this
    organization yet.`; a failed request is also rendered as an empty list.
  - `console/src/components/navigation/context-switchers.tsx:85-170` has a
    loading branch for organizations but does not expose the query error, so
    a failed organization request is reported as `No matching organizations.`
  - `console/src/components/navigation/command-palette.tsx:32-33,220-261`
    derives organization and project commands from optional query data and
    only provides `No matching command.`. It has no loading or error feedback
    while those network-backed commands are being resolved.
- Impact: Workspace navigation can falsely report that data does not exist or
  that a command does not match. Operators receive no retryable failure state.
- Suggested direction: distinguish pending, failed, and settled-empty states
  in the switchers and command palette. Keep static commands usable while
  clearly marking dynamic results as loading or unavailable.

### 3. Log rows allow unbroken operational text to escape on narrow screens

- Priority: HIGH
- Rules: R-03 and C-4
- Evidence:
  - `console/src/components/log-viewer/log-viewer.tsx:142-144` enables
    vertical scrolling but does not constrain or horizontally scroll long
    content.
  - `console/src/components/log-viewer/log-viewer.tsx:153-162` places
    `line.message` in a flex row with `whitespace-pre-wrap`, without a
    wrapping rule for long unbroken URLs, IDs, or tokens.
- Impact: A long log value can force horizontal page overflow on a phone and
  make the surrounding console difficult to operate. Log content is runtime
  data, so the component cannot assume that every message contains natural
  word boundaries.
- Suggested direction: keep the log viewport bounded and apply an explicit
  long-token policy to the message column, such as `min-w-0` with safe
  word-breaking or a deliberate horizontal scroll region.

### 4. Mobile navigation is a custom dialog without Escape or focus handling

- Priority: HIGH
- Rules: R-32 and C-4
- Evidence: `console/src/components/layout/console-shell.tsx:76-91` renders a
  fixed mobile navigation overlay with a plain `div role="dialog"` and a
  backdrop button. It has no `aria-modal`, Escape listener, focus trap, or
  focus restoration to the menu trigger.
- Impact: Keyboard users can open the mobile menu but cannot reliably close it
  with Escape, and focus can move behind the modal-like navigation. The click
  backdrop path works, but it is not an equivalent keyboard path.
- Suggested direction: use the existing dialog primitive for the mobile menu,
  or add equivalent dialog semantics, Escape handling, focus containment, and
  return-focus behavior without changing the navigation destinations.

### 5. Product-facing copy still contains forbidden U+2014 punctuation

- Priority: HIGH
- Rule: R-02
- Evidence:
  - `internal/cli/cli.go:126` prints `Stealth U+2014 Developer Cloud
    Control Plane` using the em dash character in the actual string.
  - `internal/cli/uninstall.go:331` uses the same punctuation in the
    destructive purge label.
  - `SECURITY.md:3` uses U+2014 in the security policy sentence.
  - `docs/README.md:7-15` uses U+2014 as the separator for every directory
    entry.
- Impact: The user-facing CLI and documentation fail the project's explicit
  copy rule even though the Console source was cleaned in the previous audit.
- Suggested direction: replace these separators with colons, commas, or
  parentheses. Keep the antislop rule documentation and historical audit
  records unchanged where the skill explicitly allows them.
