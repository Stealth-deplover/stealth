# Anti-slop audit 001

Date: 2026-09-12
Mode: AFTER
Scope: Stealth Console frontend and shared UI primitives

## Audit basis

The audit used the `antislop` core rules against the existing Console source.
The current branch already passes the Console typecheck, lint, unit test suite
(30 files, 128 tests), API generation, and production build. This report does
not change product code.

## Findings

### 1. Em dash appears in user-facing UI fallbacks

- Priority: HIGH
- Rules: R-02
- Evidence: `console/src/lib/format.ts:4-39` returns `"—"` for missing dates,
  bytes, counts, and durations. The same character is rendered directly in
  `console/src/features/webhooks/webhook-detail-view.tsx`,
  `console/src/features/messaging/messaging-view.tsx`,
  `console/src/features/functions/function-execution-view.tsx`, and other
  views.
- Impact: R-02 is a hard gate and forbids the em dash in UI text.
- Suggested direction: replace the fallback with product language such as
  `Not available` or an ASCII-safe equivalent, then update affected tests.

### 2. Shared button variants do not meet the skill's 44px mobile target

- Priority: HIGH
- Rules: R-03
- Evidence: `console/src/components/ui/button.tsx:22-25` defines the default
  button as `h-9` (36px), the small variant as `h-8` (32px), and the icon
  variant as `size-9` (36px). These variants are used throughout the sidebar,
  tables, dialogs, pagination, and detail views.
- Impact: compact controls can be difficult to operate on touch screens and
  fail the skill's explicit 44px target requirement.
- Suggested direction: establish a minimum 44px hit area, using visual
  padding or a larger shared variant where compact presentation is needed.

### 3. Secondary text colors fail normal-text contrast

- Priority: HIGH
- Rules: R-25
- Evidence: the palette in `console/src/app/globals.css:9-28` and recurring
  `text-slate-500`/`text-slate-600` classes use `#64748b` and `#475569`.
  Against `#080a0d`, their measured contrast is 4.16:1 and 2.62:1; against
  `#0d1015`, it is 4.00:1 and 2.51:1. Both are below 4.5:1 for normal text.
  Examples include `console/src/components/layout/topbar.tsx:56-65`,
  `console/src/components/layout/sidebar.tsx:57`, and labels across resource
  detail views.
- Impact: important labels, helper text, and controls can be unreadable for
  users who need WCAG AA contrast.
- Suggested direction: reserve the darkest slate values for decoration or
  disabled content and promote readable text tokens, then verify representative
  components against both panel and page backgrounds.

### 4. Organization overview hides query loading and error states

- Priority: HIGH
- Rules: R-27 and C-4
- Evidence: `console/src/features/organization/overview-view.tsx:16-18` starts
  organization and plan queries, but the component has no loading or error
  branch. It renders `current?.name ?? "Organization"`, empty formatted
  metrics, and `plan.data?.plan.plan_key ?? "—"` while either request is still
  pending or has failed.
- Impact: a data view can look empty or partly valid instead of communicating
  loading and failure states.
- Suggested direction: render explicit loading and error states for the
  organization and plan data, while keeping the project list's independent
  state local.

### 5. Dropdown menu items lose visible keyboard focus

- Priority: HIGH
- Rules: R-32
- Evidence: `console/src/components/ui/dropdown-menu.tsx:26-36` applies
  `outline-none` and hover-only styling to the Radix menu item. It does not
  style the keyboard-highlighted state (`data-[highlighted]`) or provide a
  replacement focus indicator. The global focus rule in
  `console/src/app/globals.css:55-69` only targets button, link, input,
  textarea, and select elements, not the Radix menu item element.
- Impact: keyboard users can move through account-menu actions without a
  reliable visible indication of the active item.
- Suggested direction: add a visible `data-[highlighted]` state with the same
  contrast and focus treatment used by the rest of the Console.

### 6. No explicit design direction or antislop dials are recorded

- Priority: HIGH
- Rules: R-37
- Evidence: the repository has no `DESIGN.md` and no design-direction block in
  the project guidance. The current UI therefore has no recorded
  `ENERGY`/`RHYTHM`/`MOTION` values for the dark palette, typography, spacing,
  or composition.
- Impact: future UI work can silently fall back to a generic style, and the
  skill's design-direction hard gate cannot be demonstrated as satisfied.
- Suggested direction: have the product owner supply a short design direction
  and record the three dials before visual changes are treated as shippable.

### 7. Decorative gradient and grid texture have no written purpose

- Priority: MEDIUM
- Rules: R-01, R-07, and R-31
- Evidence: `console/src/app/globals.css:42-48` applies a global radial
  gradient, while `console/src/app/globals.css:75-80` defines a grid texture
  used by `console/src/app/(auth)/layout.tsx:6-8`. No design direction or
  one-line purpose explains the hierarchy or identity served by either
  technique.
- Impact: these are purpose-gated visual techniques that can read as default
  AI decoration when the product identity is not documented.
- Suggested direction: document the identity/readability purpose after design
  direction is supplied, or remove the technique if it does not serve one.

### 8. Card elevation is applied globally without an elevation rationale

- Priority: MEDIUM
- Rules: R-12 and R-31
- Evidence: `console/src/components/ui/card.tsx:8-14` gives every Card the same
  large `shadow-[0_18px_60px_rgba(0,0,0,.12)]`, including ordinary data panels.
  There is no recorded reason distinguishing content grouping from elevated
  overlays.
- Impact: the interface can make every panel appear to float, weakening
  hierarchy and adding a default visual effect to all cards.
- Suggested direction: make the flat panel the default and opt into elevation
  only for dialogs, menus, or other layers that need it, with the reason
  recorded in the design direction.

## Rules with no confirmed source finding

Static review found no fabricated testimonials or statistics, no dead `href`
placeholders, and no generic marketing claims in the Console source. Navigation
items resolve to existing App Router routes based on the current route tree.
The existing `prefers-reduced-motion` rule and component-level loading/error/
empty patterns cover many views, but finding 4 remains an exception.

## Verification limitation

The repository's 33 Playwright E2E tests could not run in this environment.
Chromium launch failed because `libatk-1.0.so.0` is unavailable; installing
the OS dependencies failed because the runner has no passwordless `sudo`.
Therefore no claim is made that the full click-through and mobile breakpoint
gate passed. Unit tests, typecheck, lint, API generation, and production build
did pass before this audit.
